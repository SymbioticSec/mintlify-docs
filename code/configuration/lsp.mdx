Symbiotic Code integrates with your [Language Server Protocol](https://microsoft.github.io/language-server-protocol/) (LSP) to help the LLM interact with your codebase. It uses diagnostics to provide feedback to the LLM: after the agent edits or writes a file, any errors reported by the language server are added to the tool result so the agent can fix them.

---

LSP servers are automatically enabled when one of the above file extensions are detected and the requirements are met. Auto-installed servers are stored in `~/.local/share/symbiotic/bin/`.

<Tip>
You can disable automatic LSP server downloads by setting the `SYMBIOTIC_DISABLE_LSP_DOWNLOAD` environment variable to `true`. Servers that are already installed or available on your `PATH` still work.
</Tip>

<Note>
To use [ty](https://github.com/astral-sh/ty) instead of pyright for Python, set `SYMBIOTIC_EXPERIMENTAL_LSP_TY=true`. `ty` must be on your `PATH` or in your project's virtual environment.
</Note>

## How it works

When Symbiotic Code opens a file, it:

1. Checks the file extension against all enabled LSP servers.
2. Finds the project root for each matching server (for example the nearest lockfile, `go.mod`, or `Cargo.toml`).
3. Starts the appropriate LSP server for that root if not already running.

If a server fails to start, it isn't retried for that root until Symbiotic Code restarts.

### LSP tool (experimental)

Set `SYMBIOTIC_EXPERIMENTAL_LSP_TOOL=true` (or `SYMBIOTIC_EXPERIMENTAL=true`) to give the agent an `lsp` tool for code navigation: go to definition, find references, hover, document and workspace symbols, go to implementation, and call hierarchy. It's controlled by the `lsp` [permission](/code/security/tool_permissions).

## Configure

You can customize LSP servers through the `lsp` section in your Symbiotic Code config.

```json title="symbiotic.json"
{
  "$schema": "https://config.symbioticsec.ai/config.json",
  "lsp": {}
}
```

Each LSP server supports the following:

| Property         | Type     | Description                                       |
| ---------------- | -------- | ------------------------------------------------- |
| `disabled`       | boolean  | Set this to `true` to disable the LSP server      |
| `command`        | string[] | The command to start the LSP server. Required unless `disabled` is `true` |
| `extensions`     | string[] | File extensions this LSP server should handle. Required for custom servers |
| `env`            | object   | Environment variables to set when starting server |
| `initialization` | object   | Initialization options to send to the LSP server  |

<Warning>
Configuring a built-in server replaces how it is started: your `command` is used instead of the built-in detection and auto-install, and built-in initialization options are not sent. The server keeps its built-in extensions and root detection unless you override `extensions`.
</Warning>

Let's look at some examples.

---

### Environment variables

Use the `env` property to set environment variables when starting the LSP server:

```json title="symbiotic.json" {6-8}
{
  "$schema": "https://config.symbioticsec.ai/config.json",
  "lsp": {
    "rust": {
      "command": ["rust-analyzer"],
      "env": {
        "RUST_LOG": "debug"
      }
    }
  }
}
```

---

### Initialization options

Use the `initialization` property to pass initialization options to the LSP server. These are server-specific settings sent during the LSP `initialize` request:

```json title="symbiotic.json" {6-10}
{
  "$schema": "https://config.symbioticsec.ai/config.json",
  "lsp": {
    "pyright": {
      "command": ["pyright-langserver", "--stdio"],
      "initialization": {
        "python": {
          "pythonPath": ".venv/bin/python"
        }
      }
    }
  }
}
```

<Tip>
Initialization options vary by LSP server. Check your LSP server's documentation for available options.
</Tip>

---

### Disabling LSP servers

To disable **all** LSP servers globally, set `lsp` to `false`:

```json title="symbiotic.json" {3}
{
  "$schema": "https://config.symbioticsec.ai/config.json",
  "lsp": false
}
```

To disable a **specific** LSP server, set `disabled` to `true`:

```json title="symbiotic.json" {5}
{
  "$schema": "https://config.symbioticsec.ai/config.json",
  "lsp": {
    "typescript": {
      "disabled": true
    }
  }
}
```

---

### Custom LSP servers

You can add custom LSP servers by specifying the command and file extensions:

```json title="symbiotic.json" {4-7}
{
  "$schema": "https://config.symbioticsec.ai/config.json",
  "lsp": {
    "custom-lsp": {
      "command": ["custom-lsp-server", "--stdio"],
      "extensions": [".custom"]
    }
  }
}
```

Custom servers are started in your current working directory.
